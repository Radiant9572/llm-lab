# 学习地图：从「写不出来」到「能独立实现注意力」

> 写不出代码，99% 不是因为你不够聪明，而是**缺了某一层前置知识**。
> 这份文档的作用是帮你定位缺的是哪一层，然后只补那一层，不要从零开始重学。

---

## 一、先定位：你卡在哪一层？

对号入座，找最像你的那条。

| 层 | 症状（你的感受） | 缺的是 |
|---|---|---|
| L0 | 看到 `Q @ K.transpose(-2, -1)` 完全不知道在干什么 | 线性代数中的矩阵乘法 + 形状概念 |
| **L1** | 知道注意力大概是怎么回事，但不知道该调哪个函数、参数怎么填 | **PyTorch 张量操作**（最常见的卡点） |
| L2 | 能看懂单行代码，但不知道怎么组织成一个能跑的程序 | 神经网络训练流程（Module / 前向 / 反向 / 优化器） |
| L3 | 代码能看懂，但说不出"为什么这么做" | 注意力的数学直觉 |
| L4 | 原理都懂、代码也懂，但自己写就一片空白 | 缺少"形状优先"的推导方法（见第四节） |

**我的判断**：你大概率卡在 **L1**。因为你之前写的是 `第三章作业.ipynb` 这类数据分析作业，用的是 NumPy/pandas 的思路，而 PyTorch 的张量思维是另一套东西。

### L1 · PyTorch 张量操作 ← **最可能的卡点**

**要学什么**（按重要性排序）

1. **形状操作**：`view` / `reshape` / `transpose` / `permute` / `unsqueeze` / `squeeze`
2. **广播（broadcasting）**：为什么 `(2,3,1)` 能和 `(2,3,4)` 相减
3. **矩阵乘**：`@` 与 `*` 的区别
4. **归约**：`sum` / `max` 的 `dim` 和 **`keepdim`** 参数

6. **自动求导**：`requires_grad` / `backward()` / `.grad`

第 2 条和第 4 条是重灾区。`keepdim=True` 这一个参数，就能让 90% 的人卡住——因为不加它，`(2,3,4).sum(-1)` 会变成 `(2,3)`，再也没法和 `(2,3,4)` 相减。

## 四、核心方法：形状优先（shape first）

**这一节是整份文档里最值钱的部分。**

写不出代码的人，几乎都是因为**没有先把形状想清楚就开始写**。注意力看起来复杂，但拆开只是几步张量运算，**只要形状对了，运算几乎是唯一的**。

### 三步法

**第一步：把所有输入输出的形状写下来**

```
Q: (batch, L, d_k)
K: (batch, S, d_k)
V: (batch, S, d_v)
mask: (L, S)
输出: (batch, L, d_v)
```

**第二步：把公式拆成步骤，每一步也写形状**

```
1. scores = Q @ K^T        → (batch, L, d_k) @ (batch, d_k, S) = (batch, L, S)
2. scores = scores / √d_k  → (batch, L, S)
3. scores = mask 填充       → (batch, L, S)
4. attn = softmax(scores)  → (batch, L, S)
5. out = attn @ V          → (batch, L, S) @ (batch, S, d_v) = (batch, L, d_v)  ✓
```

**第三步：每写一行代码就 `print(x.shape)`**

不用靠脑子记，让机器告诉你。这是专业选手的习惯，不是新手才做的事。

### 为什么这招管用

因为**形状是强约束**。当你知道某一步的输出必须是 `(batch, L, S)`，而手上是 `(batch, L, d_k)` 和 `(batch, S, d_k)`，那 K 必须转置——这不是"想出来的"，是"推出来的"。

大多数时候你不需要灵感，只需要把形状对齐。

## 五、卡住时的标准动作（背下来）

1. **别盯着空白文件。** 先在纸上或注释里写下输入输出的形状。
2. **用中文写伪代码**，4-5 行，不考虑语法。
3. **一行一行翻译成 torch**，每翻译一行 `print(x.shape)`。
4. **先用最简输入跑**（`batch=1, seq_len=2`），确认能跑通。
5. **再泛化**到任意维度。

第 4 步是很多人跳过的关键步骤——先用一个手算得出的最小例子，能立刻知道对不对。
