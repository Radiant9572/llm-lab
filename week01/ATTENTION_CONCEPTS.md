# 注意力的核心概念（先读这个，再读代码）

> 写于 2026-09-10。读 `attention.py` 之前先把这个读一遍，那份代码就不再是天书了。

---

## 0. 一句话定位

**注意力 = 加权平均。权重不是人给的，是模型用相似度算出来的。**

你本科统计里学过加权平均、核平滑——注意力就是那个东西，只不过权重通过反向传播学出来。

---

## 1. 点积 = 两个向量的相似度

```
Q · K = |Q| · |K| · cos θ
```

| 两个向量的关系 | 点积 |
|---|---|
| 方向接近 | 大的正数 |
| 垂直（无关） | 接近 0 |
| 方向相反 | 负数 |

**所以"打分"这一步在问的问题就是：这个 query 和这个 key 有多像？**

这是整个注意力机制的地基。看到 `Q @ K.T` 时，脑子里应该浮现的是"算相似度矩阵"，而不是"矩阵乘法"。

---

## 2. Q / K / V 是同一个输入的三次投影

```
X  ──× W_Q──→  Q      我要找什么（查询）
   ──× W_K──→  K      我能被谁找到（标签）
   ──× W_V──→  V      我实际携带的内容（值）
```

**关键点：Q、K、V 都来自同一个 X**，只是乘了三个不同的、可学习的权重矩阵。

**招聘类比**（这个类比帮很多人一次就懂了）：

| | 类比 |
|---|---|
| Q | 岗位要求：我要招什么样的人 |
| K | 简历上的关键词标签：我有什么 |
| V | 这个人的真实能力 |

HR 拿着岗位要求（Q）去和每份简历的标签（K）匹配，匹配度高的候选人权重高，最后录用的人是所有候选人的"加权组合"。

---

## 3. 完整流程只有四步

```
① 打分      scores = Q @ K.T / sqrt(d_k)      (L, d_k) @ (d_k, S) → (L, S)
② 掩码      scores[mask == False] = -inf      (L, S) 形状不变
③ 归一化    attn = softmax(scores, dim=-1)    (L, S) 形状不变，每行和为 1
④ 加权平均  out = attn @ V                    (L, S) @ (S, d_v) → (L, d_v)
```

**注意第 ③ 步之后，注意力矩阵的每一行是一组概率分布**（和为 1）。所以第 ④ 步的输出天然落在所有 V 的凸包内——它是加权平均，不是别的。

---

## 4. 为什么要除以 √d_k

| 事实 | 说明 |
|---|---|
| Q·K 是 d_k 个乘积之和 | 每个乘积方差约 1 |
| 所以点积的方差约 d_k | 标准差约 √d_k |
| d_k 一大，分数就分布得很开 | softmax 被推向 one-hot（饱和） |
| 饱和后 | 权重几乎不再随输入变化，梯度趋近 0，模型学不动 |

除以 √d_k 把方差拉回 1，让不同维度的注意力层行为一致。

**实测数据**（跑 `attention.py` 末尾的 `experiment_scaling()` 可以自己复现）：

| d_k | 未缩放 Jacobian 范数 | 已缩放 Jacobian 范数 |
|---|---|---|
| 16 | 0.329 | 0.170 |
| 64 | 0.074 | 0.170 |
| 256 | 0.002 | 0.183 |
| 1024 | **0.0001** | 0.176 |

**一个反直觉的点**：d_k = 16 时，缩放后的值（0.170）反而比不缩放（0.329）更小。所以缩放的真正作用**不是"让梯度更大"，而是"让行为不随 d_k 崩溃"**。只看单个数据点会得出相反的错误结论。

---

## 5. 因果掩码（Causal Mask）

**解决的问题**：GPT 的任务是预测下一个词。训练时如果要预测第 3 个词，模型**不能提前看到第 4、第 5 个词**——那是作弊。但注意力默认每个位置能看到所有位置。

**做法**：

1. 注意力矩阵形状是 `(L, S)`，L = query 的数量，S = key 的数量（自注意力里 L = S = 序列长度）
2. 造一个 `(L, S)` 的 bool 矩阵，位置 `(i, j)` 为 `True` 当且仅当 `j <= i`（能看到自己和自己左边的）
3. `scores.masked_fill(~mask, -inf)` —— 屏蔽的位置变成 -∞
4. softmax 之后 `exp(-inf) = 0`，被屏蔽的位置权重自然变成 0

**形状长这样**（L = S = 5）：

```
        k1    k2    k3    k4    k5
 q1  [ True, False, False, False, False ]
 q2  [ True, True,  False, False, False ]
 q3  [ True, True,  True,  False, False ]
 q4  [ True, True,  True,  True,  False ]
 q5  [ True, True,  True,  True,  True  ]
```

下三角全 True，上三角全 False。

**两个容易忽略的点**：

- **屏蔽之后剩下的权重会被重新归一化**，仍然和为 1。所以有掩码的行不是"权重变小了"，而是"权重重新分配给了能看的位置"。
- **`(L, S)` 的掩码能广播到 `(B, H, L, S)` 上**，因为广播是右对齐的。一份掩码造一次就够，不用按 batch 和 head 复制。

## 7.1 自检参考答案

**1. 注意力在干什么**
对 V 做加权平均，权重由 Q 与 K 的相似度决定。
→ 加分：整个机制里**可学习的只有三个投影矩阵** W_Q / W_K / W_V。打分、缩放、softmax、加权求和全是确定性的数学运算。所以"注意力学到了什么"这个问题的答案是：学到了怎么打分、怎么提取信息。

**2. 点积大说明什么**
说明这个 query 和这个 key 匹配度高，该位置的 V 在输出里占更大权重。
→ 严格形式是 `Q·K = |Q||K|cos θ`。**方向接近会让点积变大，模长变大同样会。** "点积 = 相似度"是第一层直觉，严格说是"方向 × 长度"的联合信号。

**3. Q / K / V 从哪来**
不是三个不同的输入，是**同一个 X 乘三个不同的可学习矩阵**得到的三次投影。语义分工：Q = 我要找什么，K = 我能被谁找到，V = 我实际携带什么。

**4. 为什么 softmax 之前要减最大值**
防止 exp 溢出成 inf。
→ **关键：这是恒等变换，不是数值近似。** 分子分母同乘 `e^{-max}` 后约掉，结果与直接计算 `exp(x)` 在数学上完全一致。说得出这一点的人，比说得出"防止溢出"的人少一个量级。

**5. 为什么除以 √d_k 而不是 d_k**
`Q·K` 是 d_k 个近似独立的乘积之和，方差约 d_k、标准差约 √d_k。除以 √d_k 把方差拉回 1。
→ **为什么不是除以 d_k**：那会把方差压到 `1/d_k`，logits 过于集中，softmax 输出接近均匀分布，注意力失去区分度——只是从一个极端（太尖）跳到另一个极端（太平）。
→ **缩放的真正作用不是"让梯度更大"，而是"让行为不随 d_k 崩溃"。** 实测 d_k = 16 时，缩放后的 Jacobian 反而更小（0.170 vs 0.329）。只看单个数据点会得出相反的错误结论。

**6. 掩码为什么填 -inf 不填 0**
softmax 里 `exp(-inf) = 0`，权重真正归零；填 0 则 `exp(0) = 1`，**被屏蔽位置的权重反而最大**，语义完全反转。
→ 顺带一句准确表述：屏蔽的是"未来位置"，理由是"不能提前看到它们"，而不是"它们要被预测"。

**7. 有掩码的行权重之和还是 1 吗**
是。掩码后 softmax 会**重新归一化**，把概率质量重新分配给能看的位置。
→ 所以措辞上不是"权重变小了"，而是"权重重新分配了"。

**8. 因果掩码哪边为 True**
左下三角（含对角线）为 True。位置 i 只能看 `j <= i`。
→ 记忆锚点：**行 = 谁在看（query），列 = 被看的词（key）**。第 1 行只能看第 1 列，所以第 1 行只有 1 个 True。

### 追问

**追问 1：被屏蔽位置的权重是多少？**
严格等于 0（实测：`[1., -inf, -inf, 2., -inf]` → `[0.2689, 0, 0, 0.7311, 0]`，和恰为 1）。

**追问 2：整行全被屏蔽会怎样？**
输出 **nan**。因为整行都是 -inf，最大值也是 -inf，`x - max = -inf - (-inf) = nan`，后续 exp(nan) = nan。实测确认：`torch.softmax([[-inf]*5])` → `[[nan, nan, nan, nan, nan]]`。

**工程上的两种处理方式，各有代价**：

| 做法 | 结果 | 代价 |
|---|---|---|
| 用 `-float("-inf")` | 全屏蔽行产生 nan | 训练会炸 |
| 用 `-1e9` 这类大负数 | 不产生 nan | 该行变成**均匀分布**（每个位置权重 1/n），而不是全 0 —— 仍然是错的，只是错得安静 |

所以正确的做法是**从数据层面保证不会出现全屏蔽行**（padding 位置不参与计算），而不是靠换个常数糊过去。
