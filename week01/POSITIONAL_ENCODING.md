## 1 · 问题：自注意力天生不认词序

注意力做的事是"每个位置去和所有位置算相似度，然后加权平均"。

**这个过程里没有任何一步用到"位置"** —— 它只看向量之间的相似度。

所以：把输入序列打乱，注意力算出来的结果**只是跟着打乱**，本质上是同一个东西。

`position_drill.py` 的**验证 1** 实测了这个：

```
打乱词序 [2,0,3,1]，重排后最大误差 1.19e-07   ← 浮点量级，等于完全相同
```

**含义**：对纯注意力来说，**「我打你」和「你打我」是同一个句子**。

这在分类任务里可能还能忍，但在语言模型里是致命的 —— 语序就是语义的一部分。

**所以必须人为把位置信息注入进去。这就是位置编码存在的全部理由。**

> 顺带说明：`make_causal_mask`（因果掩码）解决的是另一个问题 ——「不许看未来」。
> 它管的是**可见性**，不管**顺序**。两者不能互相替代。

## 2 · 论文的做法：sin / cos 交织

论文 §3.5 的公式（`d_model` 是偶数，`i` 是维度对的编号）：

```
PE(pos, 2i)   = sin( pos / 10000^(2i/d_model) )
PE(pos, 2i+1) = cos( pos / 10000^(2i/d_model) )
```

也就是：**偶数维度放 sin，奇数维度放 cos，每一对共用同一个角频率。**

写成代码就是一个频率向量：

```python
pos   = torch.arange(seq_len).view(-1, 1)          # (seq_len, 1)
i     = torch.arange(0, d_model, 2)                # 0, 2, 4, ...
omega = torch.exp(-math.log(10000) * i / d_model)  # 1 / 10000^(2i/d_model)
pe[:, 0::2] = torch.sin(pos * omega)
pe[:, 1::2] = torch.cos(pos * omega)
```

**然后直接加到词嵌入上**（不是拼接）：

```python
x = embedding(tokens) + positional_encoding(seq_len, d_model)
```

## 3 · 三个可验证的性质（`position_drill.py` 会跑给你看）

| 性质 | 说法 | 实测 |
|---|---|---|
| **有界** | 值域永远在 `[-1, 1]`，与序列长度无关 | 长度 1024 时编号会到 1023，PE 仍是 ±1.000 |
| **可外推** | 公式对任意 `pos` 都成立，不依赖训练时的最大长度 | 周期函数，天然成立 |
| **相对位置可由线性变换表达** | `PE(pos+k)` = `PE(pos)` 经过一个**只跟 k 有关**的旋转 | 8 个维度对的最大角度误差 **1.90e-08** |

**第三条是精髓，也是"为什么用 sin/cos"的真正答案。**

每个维度对 `(sin, cos)` 本质上是一个**单位圆上的点**。位置从 `pos` 挪到 `pos+k`，
就是把这个点**旋转 `k·ω` 角度**。而旋转是**线性变换**（一个 2×2 矩阵）。

所以模型只要学会"乘某个矩阵"，就能表达"往后挪 k 个位置"这个关系 ——
**而它要学的这个矩阵跟 `pos` 无关，只跟 `k` 有关。** 这就是"容易学到相对位置"的含义。

## 4 · 为什么不用 0, 1, 2, 3…… 直接当位置？

两个具体问题（验证 3 的数据）：

**① 值域无界。** 长度 1024 时编号到 1023。而词嵌入每个分量大约在 ±1 附近 ——
把一个上千的数直接加到 ±1 的向量上，量级完全不匹配，训练会不稳。

**② 不能外推。** 训练时只见过位置 0~511，遇到 512 就是**从未见过的输入**。
而 sin/cos 是固定公式，`pos` 取任何值都算得出来。

还有一个更隐蔽的问题：即使把编号归一化到 [0,1]，模型还得自己从 `0.999` 和 `1.0`
里推出"它们差一个位置"。**差值信息藏在两个数里，对神经网络很难学。**
而 sin/cos 的旋转性质把"差值"变成了一个可以直接用线性变换表达的东西。

## 5 · 三个常见误解

**❌「位置编码是训练出来的参数」**
它不是参数，是**固定公式算出来的**（论文 §3.5 最后一句明确说 "we chose the sinusoidal version
because it may allow the model to extrapolate"）。后来才有了可学习版本（BERT）和
RoPE（现在主流，本质也是旋转，思想同源）。

**❌「位置编码要拼接到 embedding 后面」**
论文是**加法**。因为维度相同（都是 `d_model`），相加不用改变后续层的宽度。
代价是位置信息和词义信息混在同一个向量里，之后无法分开。

**❌「有了因果掩码就不需要位置编码」**
两件事：因果掩码管**可见性**（不许看未来），位置编码管**顺序**（我在第几位）。
一个模型可以"只看左边"，但仍然完全不知道左边那些词的先后。
