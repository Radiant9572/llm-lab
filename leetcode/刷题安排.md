# 力扣 Hot 100 刷题安排

**目标**：2027 年 3 月投递前，Hot 100 完整刷完一遍 + 错题复习一轮
**周期**：2026.09.11 – 2027.03.14，与 26 周计划并行
**日期**：2026-09-10

---

## 0. 先明确定位

**刷题是「防挂」，不是「加分」。**

大模型后训练 / 数据 / 评测方向的面试权重大致是：

| 权重 | 考察项 |
|---|---|
| 最高 | 项目深度（能不能讲清技术决策与归因） |
| 高 | 机器学习 / 深度学习基础、RL 原理 |
| 中高 | **手写代码能力**（不是 LeetCode，是手写 attention / loss / 采样） |
| 中 | 算法题（笔试环节为主） |

所以：
- **LeetCode 的目标是「笔试不挂」**，不是刷穿题库
- 它必须走**碎片时间**（通勤、睡前），**绝不能挤占项目实验的时间**
- 把 LeetCode 和项目放在同一时段竞争，一定是输的那个——因为项目更难、更有价值、也更容易拖延

**一句话：刷题要稳，但不能重。**

## 2. 分阶段安排（按题型，不按题号顺序）

**为什么按类型刷**：同一类题连着做，才能形成肌肉记忆。打散的顺序刷，做完 100 题你会发现自己还是不会做题，只是"见过"。

| 阶段 | 天数 | 日期 | 主题 | 题量 | 说明 |
|---|---|---|---|---|---|
| **① 数组与窗口** | D1 – D21 | 09.11 – 10.01 | 哈希 · 双指针 · 滑窗 · 子串 · 数组 · 矩阵 | 21 | 最高频，必须练到闭眼写 |
| **② 链表·树·栈** | D22 – D55 | 10.02 – 11.04 | 链表 · 二叉树 · 栈 | 34 | 指针与递归思维，最容易出错的一段 |
| **③ 图·回溯·二分·堆·贪心** | D56 – D80 | 11.05 – 11.29 | 图论 · 回溯 · 二分 · 堆 · 贪心 | 25 | 模板化程度最高，练到能默写模板 |
| **④ 动态规划与技巧** | D81 – D100 | 11.30 – 12.19 | 动态规划 · 多维 DP · 技巧 | 20 | 最难的一段，留到代码能力成熟后 |

**难度分布（已核对官方列表，并用脚本校验过）**：简单 **20** / 中等 **68** / 困难 **12**

> 困难题只有 12 道，别被"Hot 100"这个名字吓到。

- **中等题是绝对重点**——面试主战场，必须能独立限时写出
- **简单题快速过**，10 分钟内做完就跳过
- **困难题只求理解思路**，不强求独立写出。面试中困难题出现概率低，而且通常允许你说思路

## 3. 每天怎么练

**每天 1 题，30 分钟，固定时段（通勤 / 睡前）。**

关键是**固定时间点**，不是"有空就做"。到点就打开，变成条件反射——这样才能连续 100 天不断链。

为什么是每天而不是每周集中：每天 30 分钟的成本低到几乎不会失败，而"周末抽 3 小时"这件事很容易被实验挤走。而且 **100 天的连续提交记录，本身就是 GitHub 上最有说服力的东西**。

### 单题流程

1. **限时**：简单 15 分钟 / 中等 25 分钟 / 困难 40 分钟
2. **超时就去看题解，不要硬耗**
3. **看完题解后关掉，从空白重写一遍** ← 这一步不能省，省了等于没做
4. **记录一行**：题号 + 一句话关键洞察 + 时间/空间复杂度

### 记录格式（建议直接写进题解文件顶部）

```
# 3. 无重复字符的最长子串
# 关键洞察：滑动窗口的本质是"右指针扩张、左指针收缩"，用集合记录窗口内元素
# 复杂度：O(n) 时间 / O(k) 空间
# 踩坑：左指针收缩时要从集合里真正删除元素，不能只移动下标
```

### 每周复述

每周花 10 分钟，把这一周的 7 道题**口头讲一遍思路**。讲不出来的就是没掌握，重做。

## 4. 比 LeetCode 更该练的：手写实现清单

**这是最容易被忽略、但大模型岗必考的一类题——LeetCode 完全练不到。**

面试官会让你在白板或在线编辑器上，从零手写：

| 项目 | 出现在 | 你的计划里覆盖了吗 |
|---|---|---|
| 缩放点积注意力 | 几乎必考 | ✅ **W1 已练过**（`attention.py`） |
| Multi-Head Attention | 高频 | ⬜ W2 会做 |
| 数值稳定的 softmax | 高频 | ✅ **W1 已练过** |
| LayerNorm / RMSNorm | 中频 | ⬜ 建议 W2 顺手加 |
| Cross-Entropy Loss（含 log-sum-exp） | 中高频 | ⬜ 建议 P2 时补 |
| Top-k / Top-p（nucleus）采样 | 中频 | ⬜ 建议 W3 补 |
| Beam Search | 中频 | ⬜ 建议 W3 补 |
| 位置编码（正弦 / RoPE） | 中频 | ⬜ W2 会遇到正弦 |
| KV Cache 的更新逻辑 | 中频 | ⬜ P3 之后 |
| 手推 DPO 损失函数 | 后训练岗高频 | ⬜ P3 会做 |
| 手推 GRPO 优势估计 | 后训练岗高频 | ⬜ P4 会做 |
| 一个完整的训练循环（含梯度累积） | 中频 | ⬜ W3 会做 |

**好消息：这张表里超过一半会被你的 26 周计划自然覆盖。**

**要额外做的只有四件事**，都很小：
1. W2 顺手把 LayerNorm 也写一遍（和 attention 同一天做的事）
2. W3 顺手写 Top-k / Top-p 采样和 Beam Search（本来就是生成文本要用的）
3. P2 时补一个 Cross-Entropy 的手写版
4. P3 之后补 KV Cache 的更新逻辑

**建议在 `E:\llm-lab\` 下建一个 `handwritten/` 目录**，每写一个就存一个文件。**面试前一周翻一遍，比刷 50 道 LeetCode 有用。**

## 5. 语言选择

**主线用 Python。** 理由：你的主语言就是 Python，且大模型岗默认 Python。

**但要知道两个风险**：

1. **个别 OJ 的 Python 时限偏紧**，某些 O(n log n) 的题用 Python 会 TLE（超时）。LeetCode 对 Python 有单独的时限调整，一般没问题，但部分公司的自定义笔试系统没有。
2. **如果遇到 Python 超时**：先检查是不是自己的复杂度写错了，而不是急着换语言。真的需要时，用 Python 的 `sys.stdin` 快读 + 避免不必要的对象创建通常能救回来。

**不建议现在去学 C++ 刷题**——投入产出比太低，而且会挤占项目的精力。真需要时再补。

## 6. 错题本怎么做

**不需要复杂的工具。** 一个 markdown 文件，或者直接用题解文件里的 `# TODO: 二刷` 标记。

要点：

- **记"为什么错"，不要记"正确答案"**。比如"滑动窗口收缩时忘了从集合里删元素"，比抄一遍正确代码有用十倍
- **按错误类型归类**：思路错 / 边界条件漏 / 复杂度不达标 / 实现细节错。第二类最容易在面试里翻车
- **二刷只做错题**，不要重复做已经会的。时间是最稀缺的资源

## 7. 三条纪律

1. **每天 30 分钟，宁可少做不可断。** 断了三天以上，重新开始的成本远大于那三道题
2. **不许挤占项目时间。** 如果某周实验卡住需要额外时间，**砍刷题，不砍实验**——这和原计划里的止损线一致
3. **题解推到 GitHub。** 建议放在 `E:\llm-lab\leetcode\`。这既是练习记录，也是面试时"持续学习"的证明——**GitHub 上 100 天的连续提交记录，比简历上写"熟悉算法"有力得多**

---

## 8. 一句话总结

**每天 1 题、100 天刷完 Hot 100；之后约 12 周做错题二刷和模拟面试。**

每天 30 分钟，固定时段，按题型刷，错题只记"为什么错"。

**但真正决定你能不能拿 offer 的不是这 100 道题，是那三个项目。** 刷题是保险，不是发动机。
