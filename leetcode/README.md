## 记录格式

**不要背格式，直接复制模板：**

```bash
cd /e/llm-lab/leetcode
cp _TEMPLATE.py 0001_two_sum.py
```

命名 `题号_英文slug.py`，四位补零（这样文件列表能自然排序）：

| 题号 | 文件名 |
|---|---|
| 1 | `0001_two_sum.py` |
| 42 | `0042_trapping_rain_water.py` |
| 146 | `0146_lru_cache.py` |

**为什么用英文名**：中文文件名在 Windows（GBK）和 Linux（UTF-8）之间同步时反复出乱码，命令行里还得切输入法。中文题名写在文件第一行就够了。

docstring 就四个字段：

```
关键洞察：  让你豁然开朗的那一点，不是步骤
复杂度：    我的解法 O(?) ·  最优解法 O(?)   ← 两行都要写
踩坑：      我原来错在哪，没有就写"无"
结果：      独立做出 / 看题解后做出 / 看题解才懂 / 没做出来
```

**注意要记的是"关键洞察"和"踩坑"，不是正确答案。** 抄一遍正确代码没有价值，记下"我为什么没想出来"才有。

`_TEMPLATE.py` 里每个字段都有 ✗差 / ✓好 对照，填之前扫一眼。

## 每天收尾（1 分钟）

1. 在 `SCHEDULE.md` 里把今天那条勾上（`- [ ]` → `- [x]`）
2. 提交：

```bash
cd /e/llm-lab
git add -A
git commit -m "leet(D1): 0001 两数之和 O(n²) 暴力，待补哈希表优化"
git push
```

commit message 里带上**复杂度或关键结论** —— 它以后会变成你的复习索引。

## 错误类型分类（二刷时按这个筛）

| 类型 | 说明 | 优先级 |
|---|---|---|
| **思路错** | 完全没想到对的方向 | 中 |
| **边界条件漏** | 空数组、单元素、重复元素、溢出 | **最高**（面试最容易翻车） |
| **复杂度不达标** | 思路对但超时 | 高 |
| **实现细节错** | 下标、循环边界、指针更新顺序 | 高 |

二刷只做错题。**已经会做的题重复做，是在浪费最稀缺的资源。**

## 单题流程（别省第 3 步）

1. **限时**：简单 15 min / 中等 25 min / 困难 40 min
2. 超时就去看题解，**不要硬耗**
3. **看完关掉，从空白重写一遍** ← 省了这步等于没做
4. `cp _TEMPLATE.py 题号_slug.py`，填四个字段 + 贴代码

---

## 难度优先级

- **中等题是绝对重点**——面试主战场，必须能独立限时写出
- 简单题 10 分钟内做完就跳过
- **困难题只求理解思路**，不强求独立写出
